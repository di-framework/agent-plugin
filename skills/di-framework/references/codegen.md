# Schema codegen

`@di-framework/codegen` turns a typed manifest into deterministic glue. You own schemas, the manifest, and handlers. The generator owns files under the output directory that start with the ownership header. Inspect the resolved version; the inspected sibling checkout publishes **6.0.3**. Guide: <https://docs.di-framework.dev/codegen.html>.

```bash
bun add -d @di-framework/codegen @di-framework/cli
```

`@di-framework/core` is a peer. Also install the packages for the surfaces you emit (`@di-framework/http`, `events`, `rpc`, `ai`, `authz`). Discovery uses `Bun.Glob`; run `di-framework generate` with Bun. Direct file paths work in any runtime.

## Layout

```text
di-framework.codegen.ts
src/contracts/orders.schemas.ts       # hand-written RuntimeSchema
src/contracts/orders-v1.codegen.ts    # hand-written manifest
src/handlers/order.handlers.ts        # --init once, then yours
src/policies/order.policy.ts          # --init once, then yours
src/generated/orders/v1/              # contracts.ts plus optional http, events, rpc, tools
src/generated/.codegen-ledger.json
```

Each manifest writes `<outDir>/<name>/<version>/`, so `v1` and `v2` coexist. Config resolution order: `di-framework.codegen.ts`, `di-framework.codegen.js`, `codegen.config.ts`, `codegen.config.js`, then defaults. Override with `--config`.

```ts
export default {
  manifests: ['./src/contracts/**/*.codegen.ts'],
  outDir: './src/generated',
  companionsDir: './src/handlers',
  policiesDir: './src/policies',
} satisfies CodegenConfig;
```

## Manifest rules

A manifest `satisfies SchemaCodegenManifest`: `name`, `version`, `schemas`, and `operations`. Schemas are `RuntimeSchema` values with `parse` and `jsonSchema` (Zod `z.toJSONSchema` is the usual source). Operation `input` / `output` name schema keys.

`handler.module` / `export` / `method` point at a hand-written class. HTTP, events, RPC, and tools all validate input, call that method, and validate output. The handler receives the transport name; HTTP also receives the request.

Emit `http.ts` when an operation has `http` or the manifest sets `http.prefix`. `events.ts`, `rpc.ts`, and `tools.ts` emit only for operations that declare those blocks. `managedByDi: true` registers the generated controller with the container. Generated routes carry `@Endpoint` metadata, so `di-framework http openapi generate` can document them. Read [http.md](http.md) before changing route behavior.

## Commands

```bash
di-framework generate
di-framework generate --init
di-framework generate --check
di-framework generate --clean
```

`--init` creates missing handler and policy skeletons and does not overwrite existing files. `--check` exits `1` on drift and writes nothing; use it in CI. `--clean` deletes only ledger files that still carry `// @generated by @di-framework/codegen — do not edit.` Do not hand-edit generated files. Change the manifest and regenerate.

Programmatic entry: `generate({ config, init, check, clean })` from `@di-framework/codegen`. JSON `data` is `GenerateResult` (`success`, `drifted`, `files`, `ledgerPath`, `diagnostics`). Unknown CLI arguments exit `2`.
